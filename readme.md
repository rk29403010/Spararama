# Spa Monitor
## Functional Specification
- **Initial Setup:** Configured default app state for the 'CleverSpa 800L' inflatable hot tub parameters (1800W heating, 600W bubbling, 800L capacity).
- **Chemical Inventory Tracking:** A new scanner utility uses device cameras and multimodal AI to read chemical barcodes, parsing active ingredients and quantities to build a stock list.
- **Smart Test Strip Reader:** Added an automated test strip reader. It includes a 15-second visual and auditory countdown timer so users know exactly when to dip and extract the strip. The AI then processes the photo to estimate Free Chlorine, pH, and Alkalinity, offering targeted dosing recommendations.
- **Predictive Heating Calculator:** A new dynamic scheduling tool. Users input their current water temperature and desired "ready-by" time. It fetches regional weather forecast data (Open Meteo) to estimate ambient thermal loss, then calculates the exact time to activate the 1800W heater and projects the session's energy cost.
- **Redesigned Heating UI (v0.1.2):** Redesigned the heating schedule page for maximum simplicity. Added prominent vertical thermometer sliders for Current and Target temperatures. The scheduling controls were simplified to a "Today/Tomorrow" toggle and time input, with automatic calculation debouncing. Everything fits on a single mobile viewport without scrolling.
- **Temperature Scale Settings (v0.1.2):** Added a global toggle in the Config tab to switch the application between Celsius and Fahrenheit.
- **Heating UI Refinements (v0.1.3):** Further streamlined the Heating view by integrating the temperature values directly inside the blue slider thumbs. A central vertical scale with key temperatures provides quick visual reference. The target time selection is now a compact hour-only dropdown (supporting both 12h and 24h formats) that automatically toggles between Today and Tomorrow depending on the current time.
- **Settings Persistence & Defaults (v0.1.3):** Expanded the configuration options to include Time Format (12h/24h) and a Default Tub Time. Ensured robust local storage persistence for all user preferences, with guaranteed defaults for seamless onboarding.
- **Heating UI Visual Fixes (v0.1.4):** Fixed the z-index and position calculation of the dynamic temperature value bubbles on the heating sliders. The values are now correctly displayed above the slider track and map precisely to the thumb's vertical location along the scale.
- **Heating Layout Reorder (v0.1.5):** Moved the calculated start time and estimated cost display to the bottom of the screen, below the temperature sliders and target time selectors, to create a more natural top-to-bottom user flow (input to output).
- **Persistent Cloud Activity Logs (v0.1.6):** Implemented a new Firebase-powered "Logs" tab to durably record user activity over time. Chemical readings (pH, Chlorine, Alkalinity) are automatically stored after scanning, and a new "Save Calculation" button in the Heating view allows users to manually archive predictive heating estimates. This creates a persistent history for long-term usage tracking and cost analysis across devices.
- **Weather-Aware Heating Predictions (v0.1.7):** Integrated the public Open-Meteo forecast API to dynamically fetch ambient temperature and wind speed for the projected heating window. The base heating rate is now automatically penalized for cold weather (<15°C) and high wind speeds (>10km/h), yielding more accurate, weather-adjusted startup times and cost estimates. Weather averages are visually surfaced in the UI and persisted to the Firebase Activity Logs upon saving.
- **Configurable Electricity Rate (v0.1.8):** Added a dedicated setting in the configuration tab to adjust the electricity unit rate (per kWh). The default rate has been updated to £0.2086 to better reflect current averages, ensuring more precise cost estimates for predicted heating sessions.
- **Error Handling & Stability (v0.1.9):** Fixed an issue where anonymous authentication failure would prevent activity logs from loading by relaxing strict Firestore security rules for this environment and swallowing harmless auth console errors. Added graceful fallback for the Open-Meteo weather API to prevent unhandled 503 errors from crashing the app when the service is unavailable. Finally, updated the server API route to use the correct `gemini-2.5-flash` model for chemical test analysis.
- **Heating Reminders & Manual Logs (v0.1.10):** Replaced the static "Save Calculation" button with a dynamic "Set Reminder" workflow. Users can now schedule browser notifications for when they need to start heating or when the tub is ready. When a reminder triggers, the app prompts the user to verify the actual temperature to help self-calibrate future predictions. Additionally, introduced a floating action button to manually log free-form temperature readings, cover status (on/off), and session entry/exit at any time, all of which stream securely to Firebase. Finally, resolved a UI bug causing the heating sliders to overlap the top navigation bar.
- **Configurable Default Target Temperature (v0.1.11):** Added a new setting to define the default target temperature, initializing to 40°C. The heating screen now reads from this preference when initializing, and correctly adapts default targets across scale conversions (Celsius/Fahrenheit) for faster daily setup.
- **Mobile-First Manual Logging (v0.1.12):** Completely redesigned the manual logging modal to prioritize quick, one-handed touch interactions around the hot tub. Standard dropdowns have been replaced with large, icon-driven tactile buttons for common actions (Heater On/Off, Get In/Out, Note Temp). Replaced the standard number input for temperature with an interactive visual slider mirroring the Heating view. Re-engineered the time selection to default to "Now" (snapped to the nearest 5 minutes) with simple toggle controls for quick historical adjustments, drastically speeding up data entry without typing.
- **Log Screen Enhancements (v0.1.13):** Refined the manual logging experience: checking "Get In/Out" automatically toggles the cover status appropriately, while temperature sliders have been upgraded with reference marks at 20° and 30° and a centered dynamic value readout to maximize touch space. Also introduced a new field to track and note any pump/hardware "Rattle" sounds during operation.
- **Dynamic Camera Permissions (v0.1.14):** Removed the upfront camera permission request from the application manifest. The camera prompt will now only trigger dynamically when a user actually initiates a barcode or test strip scan, improving the initial onboarding experience.
- **Activity Trends Visualization (v0.1.15):** Integrated a dual-axis Recharts graph at the top of the Activity History tab. It plots historical temperature readings alongside estimated heating costs, giving users an immediate visual understanding of their hot tub usage and efficiency over time without needing to scan individual log entries.
- **Improved Target Time Notifications & Heat Soak (v0.1.16):** Enhanced the "Tub should be ready" reminder modal by replacing the standard temperature input with the interactive visual slider (defaulting to the target temperature). Also replaced the save workflow with two quick-action buttons: "😁 Getting In" (saves log with entry flag) and "🙁 Another 10m" (saves current temp and sets a new reminder for 10 minutes). Additionally, introduced a new "Heat Soak Time" setting in the Config tab that adjusts the heating prediction algorithm, shifting the start time earlier to ensure the tub has enough time to evenly heat the full volume of water before entry.
